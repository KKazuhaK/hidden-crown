# Implementation decisions

Choices below fill gaps in the revised build spec. They add no gameplay mechanics.

1. **Location:** the repo lives in `hidden-crown/` inside the supplied workspace, matching the spec's root directory.
2. **Toolchain:** Node.js 24+ is required for the self-hosted runtime and its built-in SQLite API. Vitest 4.1.11+ avoids the known mock-redirect dependency advisory. `package-lock.json` fixes installed versions. The frontend has no build step; esbuild bundles the server.
3. **Room IDs:** eight uppercase characters from `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`. The alphabet has 32 symbols, so byte modulo 32 is unbiased. A collision retries creation up to three times. No lowercase look-alike characters are used.
4. **Atomic state/log:** SQLite-backed Durable Object storage's key/value API stores `state` and `log` together in a transaction. The logical `log` array only appends. Meaningful events persist before broadcasting; read-only `ping`, `get_log` and `get_links` do not cause unnecessary state writes. Constructor reloads both keys after every wake.
5. **Event serialization:** short `blockConcurrencyWhile` handlers serialize messages and close events across storage awaits. An attachment marked inactive excludes a replaced socket immediately; its delayed close cannot mark its replacement offline or append a duplicate departure. Replacement records a `left` event with `replaced: true` followed by the new `joined` event in the same commit.
6. **Connection defenses:** HTTP/WebSocket browser origins must match the host when an Origin header is present. Unknown rooms reject upgrades. Unauthenticated connections have a 15-second hello deadline enforced by a storage alarm, with at most eight pending sockets. This is transport housekeeping, not a gameplay time limit. No persistent timer runs inside the room.
7. **View allowlist:** `viewFor` explicitly copies permitted fields. New server-only fields cannot be exposed accidentally. Both public locked flags are visible; the opponent's crown ID mapping is absent before the end. Player access to logs and invitation links is rejected with a role-only error independent of crown choice.
8. **Link envelope:** `get_links` replies with `{ type: "links", links: { white, black, observer } }`. These are fragment-token relative URLs. The observer requests them after authentication so Copy player links stays a direct user-click clipboard action. No token is logged.
9. **Reconnect storage:** a fragment token wins over the current tab's sessionStorage token. White/Black resume credentials use separate localStorage keys; room-number Join never automatically uses them. This fixes a browser-wide credential incorrectly treating the second player as a reconnect and replacing the first.
10. **Transport health:** heartbeat every 25 seconds as specified; missed responses for 65 seconds trigger reconnect. Backoff is 1, 2, 4, 8, then repeated 10 seconds. Closure 4000 (replacement) and 4001 (invalid token) stop reconnecting so tabs do not steal the same role back and forth.
11. **Confirmation dialogs:** native HTML `<dialog>` elements confirm crown locking and resignation and support Cancel/Escape. Promotion also uses a modal four-choice picker. This keeps confirmation styling and accessibility consistent on phone and desktop.
12. **Rendering (revised at user request):** original local SVG silhouettes replace font-dependent piece symbols on the board, captured trays and promotion picker. Server-confirmed moves animate for 360 ms, including both pieces in castling and a fade for captures; promotion retains the pawn during travel and changes its graphic at arrival. Reduced-motion preferences skip movement. New initial/reconnect snapshots do not replay old moves. Black's board is flipped; the observer uses White's orientation. The previous move is indicated only by two origin/destination squares. Following the user's Chess.com reference, a half-transparent yellow overlay preserves the underlying light/dark board colors; no arrow or extra text is added. Permanent IDs and the existing view allowlist preserve crown privacy and captured-crown reveal.
13. **Notation:** a single space before `e.p.` follows the acceptance example (`e5xd6 e.p.`). There are never check/mate suffixes. Promotion notation uses the original pawn movement, with its promoted type in the suffix.
14. **Times:** observer timing uses `serverNow` anchored to monotonic `performance.now()`, so local wall-clock skew does not distort the live duration. The previous `lastMoveAt`/`playStartedAt` is read before applying the new timestamp. JSON remains English; CSV timestamps are ISO 8601 UTC with CRLF rows and quoted/escaped fields.
15. **Reveal wording:** identify each crowned piece by color/type and its original starting square, with the actual capture square when captured. This distinguishes original same-type pieces even after they have moved.
16. **Draw handling:** any move clears an offer, as specified. Only the opposite player may answer it. No repetition-based draw is added. No-moves and 100-ply detection use the specified precedence after crown capture. Resignation is allowed only during play.
17. **Retention:** rooms and logs are not automatically deleted or expired; the spec needs the research record available for later export. There is no restart/rematch button; create a new room for the next pair/session.
18. **Validation boundary:** automated clients and browser smoke games validate implementation only. They do not substitute for the researcher's recorded session, consent or different-network acceptance. Production deployment uses the user's server, domain and administrator credentials; Docker images have not been published. The retained Cloudflare preview requires a separate account login.
19. **Room-number entry (revised at user request):** `POST /api/rooms/<roomId>/join` returns `choose_side` when both seats are available and no color was selected. The first player submits `color: w|b`; a later player always receives the remaining seat. Claims are persisted and serialized, so concurrent choices cannot allocate the same seat. Join accepts no credentials or observer role. Recovery is an explicit separate action. Reservations have no timeout; private player links can recover the seat.
20. **Self-hosting (user-requested addition):** the production target is a single Node process with SQLite, Docker and Nginx. State/log are stored atomically in one SQLite row; per-room queues reuse the same room core as the Cloudflare adapter. The Node admission/security layer applies globally and is not provided by the retained Worker preview. Deployment files and tag-based GHCR AMD64/ARM64 release workflows are included; publication has not run.
21. **Admin-only god view (user-requested replacement):** public creation no longer returns observer links, and observer-token authentication is disabled. `/admin` uses a configurable account/password and a server-side session. An authenticated admin socket receives an observer view through its cookie, without a public role token and without replacing other admin sockets. The user authorized force-end and deletion; UI confirmations, CSRF, audit and connection revocation cover these actions. Force-end is moderation, not a new gameplay draw rule.
22. **Abuse/resource bounds:** creation/login/HTTP/upgrade/message limits use bounded token buckets; global room/database/connection/cache/queue limits complement IP controls. Exact trusted proxy addresses are required for forwarding headers. State is not expired or silently pruned; admins export and remove unwanted rooms. Docker CPU/memory/process limits and Nginx throttles provide outer resource constraints. See DEPLOYMENT.md for exact defaults and limits.
